# 04 · 视图 / 存储过程 / 触发器

## 目标

会创建简单视图与存储过程，理解触发器的触发时机与适用边界；知道「什么时候不该用」。

## 大纲

### 1. 视图（VIEW）

- 概念：基于 SQL 查询的虚拟表  
- 用途：简化复杂查询、权限控制、逻辑复用  
- 限制：更新视图有约束；复杂视图常只读

```sql
CREATE VIEW v_emp_dept AS
SELECT e.name, d.name AS dept_name
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.id;

SELECT * FROM v_emp_dept;
DROP VIEW v_emp_dept;
```

### 2. 存储过程（PROCEDURE）

- 概念：一组预编译的 SQL 逻辑，可带参数  
- 用途：封装多步写操作、减少往返（慎用）  
- 基本结构：`CREATE PROCEDURE` / `CALL` / `DROP PROCEDURE`

```sql
DELIMITER //
CREATE PROCEDURE p_emp_count(IN p_dept_id INT, OUT p_cnt INT)
BEGIN
  SELECT COUNT(*) INTO p_cnt FROM emp WHERE dept_id = p_dept_id;
END //
DELIMITER ;

CALL p_emp_count(1, @cnt);
SELECT @cnt;
```

### 3. 触发器（TRIGGER）

- 概念：在表事件前后自动执行的逻辑  
- 时机：`BEFORE` / `AFTER` × `INSERT` / `UPDATE` / `DELETE`  
- 典型：审计日志、冗余字段同步（业务复杂时易难维护）

```sql
-- 示例骨架（按需展开）
CREATE TRIGGER trg_emp_bi
BEFORE INSERT ON emp
FOR EACH ROW
BEGIN
  -- NEW.col := ...
END;
```

### 4. 选型与边界

| 对象 | 适合 | 慎用 |
|------|------|------|
| 视图 | 读模型简化、权限裁剪 | 当「万能业务层」 |
| 存储过程 | 库内强一致批处理、遗留系统 | 复杂业务全堆在库里 |
| 触发器 | 轻量审计、简单联动 | 隐式副作用多、难排查 |

## 小结

- 视图是查询的封装；过程是逻辑的封装；触发器是事件驱动  
- 能放应用层更清晰的，就别硬塞进库  
- 调试成本：触发器 > 过程 > 视图

## 常见坑 / 面试点

- `DELIMITER` 在客户端里写多语句时的用法  
- 触发器递归 / 互相触发导致死循环  
- 面试：视图能否更新；触发器与应用代码职责划分
