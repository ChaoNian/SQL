# 06 · InnoDB

## 目标

在「事务 / 锁」基础上，建立 InnoDB 核心组件直觉：聚簇索引、MVCC、Undo/Redo、缓冲池；能把隔离级别与实现手段对应起来。

## 大纲

### 1. InnoDB 定位

- MySQL 默认事务引擎  
- 特点：行锁、MVCC、崩溃恢复、外键（可选）

### 2. 逻辑存储与索引

- 表空间 / 页（通常 16KB）直觉  
- **聚簇索引**：叶子存完整行；主键选择很重要  
- **二级索引**：叶子存主键值 → 可能回表

### 3. MVCC 与读写并发

- 多版本：读不阻塞写、写不阻塞读（常见场景）  
- 隐藏列 / Undo 版本链直觉  
- `READ COMMITTED` vs `REPEATABLE READ` 在版本可见性上的差异（入门级）

### 4. 日志体系

| 日志 | 作用 |
|------|------|
| Redo Log | 崩溃恢复，保证持久性 |
| Undo Log | 回滚与 MVCC 读历史版本 |
| Binlog | 服务层日志，主从复制 / 恢复（与引擎协作） |

- 两阶段提交：Redo 与 Binlog 一致（概念了解即可）

### 5. Buffer Pool

- 缓存页数据与索引，命中率影响性能  
- 脏页刷盘与 `innodb_buffer_pool_size`（参数级了解）

### 6. 与隔离级别的对应（串起来）

- 脏读 / 不可重复读 / 幻读  
- RR 下 InnoDB 用 MVCC + 间隙锁等缓解幻读  
- `SERIALIZABLE` 更偏锁串行，并发代价高

## 小结

- InnoDB = 聚簇表 + MVCC + Redo/Undo + Buffer Pool  
- 主键与二级索引设计直接影响访问路径  
- 学锁与事务时，最终都落到这些机制上

## 常见坑 / 面试点

- 二级索引一定回表吗？覆盖索引可以不回  
- Undo 不是「无限历史」，有清理线程  
- 面试：MVCC 是什么；Redo 与 Binlog 区别
