# 02 · 索引

## 目标

理解索引用途与代价，掌握常见索引类型与创建语法，知道「该不该建、建在哪」的基本原则。

## 大纲

### 1. 为什么需要索引

- 没有索引：全表扫描  
- 有索引：类似书的目录，加速定位  
- 代价：占空间；写（INSERT/UPDATE/DELETE）变慢

### 2. 索引结构直觉

- InnoDB：**B+ 树**为主（聚簇索引 / 二级索引）  
- 哈希索引：Memory 引擎等场景（了解）  
- 不要求默写页分裂细节，先建立「有序树 + 回表」直觉

### 3. 索引分类

| 分类维度 | 类型 | 说明 |
|----------|------|------|
| 功能 | 主键 / 唯一 / 普通 / 全文 | 约束与检索能力不同 |
| 结构 | 单列 / 联合（复合） | 联合索引注意最左前缀 |
| 存储 | 聚簇索引 / 二级索引 | InnoDB 主键即聚簇 |

### 4. 语法

```sql
-- 创建
CREATE INDEX idx_emp_name ON emp(name);
CREATE UNIQUE INDEX uk_emp_idcard ON emp(idcard);
CREATE INDEX idx_emp_name_age ON emp(name, age);  -- 联合索引

-- 建表时
CREATE TABLE t (
  id INT PRIMARY KEY,
  name VARCHAR(50),
  INDEX idx_name (name)
);

-- 查看 / 删除
SHOW INDEX FROM emp;
DROP INDEX idx_emp_name ON emp;
```

### 5. 使用原则（先记这些）

- 高区分度列更适合建索引（如手机号；性别通常不适合单独建）  
- 联合索引遵守**最左前缀**  
- 避免过多索引；先覆盖高频 WHERE / JOIN / ORDER BY  
- 索引列上尽量避免函数运算、隐式类型转换

### 6. 覆盖索引与回表（入门）

- 回表：二级索引找到主键后再回聚簇索引取整行  
- 覆盖索引：查询列都能在索引中拿到，少回表

## 小结

- 索引换时间，用空间和写性能换读性能  
- InnoDB 主键很重要；联合索引看最左前缀  
- 先会建/删/看，再结合 `EXPLAIN` 验证是否用上

## 常见坑 / 面试点

- `LIKE '%xx'` 通常无法很好用 B+ 树索引  
- 选错主键（UUID、过长）影响聚簇索引效率  
- 面试：最左前缀、覆盖索引、主键与聚簇索引关系
