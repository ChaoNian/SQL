# 04 · 约束

## 概述

**概念**：约束是作用于表中字段上的规则，用于限制存储在表中的数据。

**目的**：保证数据库中数据的正确、有效和完整。

## 分类

| `FOREIGN KEY`约束 | 描述                           | 关键字           |
| --------------- | ---------------------------- | ------------- |
| 非空约束            | 限制该字段的数据不能为 null             | `NOT NULL`    |
| 唯一约束            | 保证该字段的所有数据都是唯一、不重复的          | `UNIQUE`      |
| 主键约束            | 主键是一行数据的唯一标识，要求非空且唯一         | `PRIMARY KEY` |
| 默认约束            | 保存数据时，如果未指定该字段的值，则采用默认值      | `DEFAULT`     |
| 检查约束            | （8.0.16 版本之后才有效）保证字段值满足某一个条件 | `CHECK`       |
| 外键约束            | 用来让两张表的数据之间建立连接，保证数据的一致性和完整性 | `FOREIGN KEY` |

---

## 创建表（综合演示各约束）

```sql
CREATE TABLE user (
  id     INT PRIMARY KEY AUTO_INCREMENT COMMENT '主键',
  name   VARCHAR(10) NOT NULL UNIQUE COMMENT '姓名',
  age    INT CHECK (age > 0 AND age <= 120) COMMENT '年龄',
  status CHAR(1) DEFAULT '1' COMMENT '状态',
  gender CHAR(1) COMMENT '性别'
) COMMENT '用户表';

-- 插入数据
insert into user(name, age, status, gender) values ('tom1', 19, '1', '男'),('Tom2', 25, '0', '男');
```

对应约束：

| 字段 | 用到的约束 |
|------|------------|
| `id` | 主键 `PRIMARY KEY` + 自增 `AUTO_INCREMENT` |
| `name` | 非空 `NOT NULL` + 唯一 `UNIQUE` |
| `age` | 检查 `CHECK`（年龄 1~120） |
| `status` | 默认 `DEFAULT '1'` |
| `gender` | 无额外约束 |

> 注意：`CHECK` 里用 `AND`，不要用 `&&`；最后一个字段后不要多写逗号。

## 3. 外键约束

**概念**：外键用来让两张表的数据之间建立连接，从而保证数据的一致性和完整性。

### 示例：员工表 emp ↔ 部门表 dept

| 角色 | 表 | 关联字段 |
|------|-----|----------|
| 子表（从表） | `emp` 员工表 | `dept_id`（外键） |
| 父表（主表） | `dept` 部门表 | `id`（主键） |

关系：`emp.dept_id` → `dept.id`（员工属于哪个部门）

部门表示例：

| id | name |
|----|------|
| 1 | 研发部 |
| 2 | 市场部 |
| 3 | 财务部 |
| 4 | 销售部 |
| 5 | 总经办 |

员工表中 `dept_id` 存的是部门主键，例如：金庸 `dept_id=5`（总经办），张无忌等 `dept_id=1`（研发部）。

> **注意**：若两张表在数据库层面未建立外键关联，就无法由数据库保证数据的一致性和完整性（例如可以写入不存在的 `dept_id`）。

### 语法 · 添加外键

**建表时添加：**

```sql
CREATE TABLE 表名(
  字段名 数据类型,
  ...
  [CONSTRAINT] [外键名称] FOREIGN KEY (外键字段名) REFERENCES 主表(主表列名)
);
```

**建表后添加：**

```sql
ALTER TABLE 表名 ADD CONSTRAINT 外键名称 FOREIGN KEY (外键字段名) REFERENCES 主表(主表列名);
```

### 实操：dept / emp

```sql
-- 部门数据
INSERT INTO dept (id, name) VALUES
  (1, '研发部'), (2, '市场部'), (3, '财务部'), (4, '销售部'), (5, '总经办');

-- 员工表（先建表，暂不声明外键）
CREATE TABLE emp(
  id        INT AUTO_INCREMENT PRIMARY KEY COMMENT 'ID',
  name      VARCHAR(50) NOT NULL COMMENT '姓名',
  age       INT COMMENT '年龄',
  job       VARCHAR(20) COMMENT '职位',
  salary    INT COMMENT '薪资',
  entrydate DATE COMMENT '入职时间',
  managerid INT COMMENT '直属领导ID',
  dept_id   INT COMMENT '部门ID'
) COMMENT '员工表';

INSERT INTO emp (id, name, age, job, salary, entrydate, managerid, dept_id) VALUES
  (1, '金庸', 66, '总裁', 20000, '2000-01-01', NULL, 5),
  (2, '张无忌', 20, '项目经理', 12500, '2005-12-05', 1, 1),
  (3, '杨逍', 33, '开发', 8400, '2000-11-03', 2, 1),
  (4, '韦一笑', 48, '开发', 11000, '2002-02-05', 2, 1),
  (5, '常遇春', 43, '开发', 10500, '2004-09-07', 3, 1),
  (6, '小昭', 19, '程序员鼓励师', 6600, '2004-10-12', 2, 1);

-- 添加外键：emp.dept_id → dept.id
ALTER TABLE emp ADD CONSTRAINT fk_emp_dept_id FOREIGN KEY (dept_id) REFERENCES dept(id);
```

### 语法 · 删除外键

```sql
ALTER TABLE 表名 DROP FOREIGN KEY 外键名称;

-- 例：删除 emp 上的部门外键
ALTER TABLE emp DROP FOREIGN KEY fk_emp_dept_id;
```

### 外键行为（删除 / 更新行为）

父表记录被删除或更新时，可通过 `ON DELETE` / `ON UPDATE` 指定子表外键的处理方式。

| 行为 | 说明 |
|------|------|
| `NO ACTION` | 当在父表中删除/更新对应记录时，首先检查该记录是否有对应外键，如果有则不允许删除/更新。（与 `RESTRICT` 一致） |
| `RESTRICT` | 当在父表中删除/更新对应记录时，首先检查该记录是否有对应外键，如果有则不允许删除/更新。（与 `NO ACTION` 一致） |
| `CASCADE` | 当在父表中删除/更新对应记录时，首先检查该记录是否有对应外键，如果有，则也删除/更新外键在子表中的记录 |
| `SET NULL` | 当在父表中删除对应记录时，首先检查该记录是否有对应外键，如果有则设置子表中该外键值为 `null`（要求该外键列允许为 `null`） |
| `SET DEFAULT` | 父表有变更时，子表将外键列设置成一个默认的值（InnoDB 不支持） |

```sql
ALTER TABLE 表名 ADD CONSTRAINT 外键名称 FOREIGN KEY (外键字段) REFERENCES 主表名（主表字段名）ON UPDATE CASCADE ON DELETE  CASCADE

-- 语法示例（建表时 / 添加外键时均可加）
ALTER TABLE emp
  ADD CONSTRAINT fk_emp_dept_id
  FOREIGN KEY (dept_id) REFERENCES dept(id)
  ON UPDATE CASCADE
  ON DELETE SET NULL;
```

- 默认多为 `RESTRICT` / `NO ACTION`（有引用则拒绝删改父表）
- 父子表插入、删除顺序仍需注意
- 引擎需为 InnoDB

## 4. 何时慎用外键（实践视角）

- 优点：数据库强制一致
- 代价：写入开销、迁移与分库难度、批量导入顺序
- 面试常答：强一致小系统可用；高并发/分片场景常下沉到应用

## 小结

- 主键唯一标识；唯一约束防重复；非空与默认管单列质量
- CHECK 在 8.0.16+ 才可靠；外键管表间引用
- 外键是一致性工具，不是无条件最优解

## 常见坑 / 面试点

- 一张表只能有一个主键，可以是单列或联合主键
- 唯一索引与唯一约束的关系（实现上常靠唯一索引）
- MySQL 旧版本「支持 CHECK 语法但不强制」的历史坑
- 外键列类型必须与被参照列兼容（含符号、长度）
