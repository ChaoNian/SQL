# 04 · 约束

## 目标

理解并会声明常用完整性约束，知道外键的行为与使用取舍。

## 大纲

### 1. 约束解决什么问题

- 实体完整性、域完整性、参照完整性（直觉理解即可）  
- 约束在「写」路径拦脏数据，比只靠应用层更稳

### 2. 常见约束类型

| 约束 | 作用 |
|------|------|
| `PRIMARY KEY` | 唯一标识一行；隐含 NOT NULL + UNIQUE |
| `UNIQUE` | 值唯一，允许（通常一个）NULL，视版本/引擎细节 |
| `NOT NULL` | 禁止空 |
| `DEFAULT` | 缺省值 |
| `CHECK` | 自定义条件（MySQL 8.0.16+ 真正生效） |
| `FOREIGN KEY` | 参照另一表主键/唯一键 |

### 3. 声明时机

- 建表时列级 / 表级约束  
- `ALTER TABLE ... ADD CONSTRAINT`  
- 删除约束的基本写法（了解）

### 4. 外键行为

- `ON DELETE` / `ON UPDATE`：`RESTRICT`/`NO ACTION`、`CASCADE`、`SET NULL`  
- 父子表插入、删除顺序  
- 引擎需为 InnoDB

### 5. 何时慎用外键（实践视角）

- 优点：数据库强制一致  
- 代价：写入开销、迁移与分库难度、批量导入顺序  
- 面试常答：强一致小系统可用；高并发/分片场景常下沉到应用

```sql
SHOW CREATE TABLE orders\G

-- 违反外键会失败的示例（具体 id 以种子数据为准）

```

## 小结

- 主键唯一标识；唯一约束防重复；非空与默认管单列质量  
- CHECK 在 8.0.16+ 才可靠；外键管表间引用  
- 外键是一致性工具，不是无条件最优解

## 常见坑 / 面试点

- 一张表只能有一个主键，可以是单列或联合主键  
- 唯一索引与唯一约束的关系（实现上常靠唯一索引）  
- MySQL 旧版本「支持 CHECK 语法但不强制」的历史坑  
- 外键列类型必须与被参照列兼容（含符号、长度）
