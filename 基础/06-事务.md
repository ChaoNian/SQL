# 06 · 事务

## 目标

理解 ACID 与提交/回滚，能关闭自动提交并演示「扣库存 + 下单」失败回滚；对隔离级别有直觉。

## 大纲

### 1. 事务与 ACID

- Atomicity 原子性：要么全成，要么全不成  
- Consistency 一致性：约束与业务不变量不被破坏  
- Isolation 隔离性：并发事务互不干扰的程度  
- Durability 持久性：提交后不丢

### 2. 基本语法与自动提交

- `START TRANSACTION` / `BEGIN`  
- `COMMIT`、`ROLLBACK`  
- `autocommit`：会话默认常为开；查/改：`SELECT @@autocommit`  
- 隐式提交：部分 DDL 会提交当前事务（知晓即可）

### 3. 隔离级别概览

| 级别 | 直觉 | 典型现象（可能） |
|------|------|------------------|
| READ UNCOMMITTED | 能读到别人未提交 | 脏读 |
| READ COMMITTED | 只读已提交 | 不可重复读 |
| REPEATABLE READ | MySQL InnoDB 默认 | 幻读（InnoDB 下多有缓解） |
| SERIALIZABLE | 最强 | 并发下降 |

### 4. 并发问题直觉

- 脏读、不可重复读、幻读分别是什么（举例级）  
- 不要求背引擎实现细节（MVCC / 间隙锁留给进阶）

### 5. 实战示例：扣库存 + 下单

- 步骤：开事务 → 检查并扣 `product.stock` → 写 `orders` / `order_item` → 成功则 `COMMIT`，任一步失败 `ROLLBACK`  
- 对比：中途报错若不回滚，可能留下半成品数据

## 示例（占位 · 依赖 demo）

```sql
USE demo;

SET autocommit = 0;

START TRANSACTION;

-- 1) 扣库存（示例 id/数量以种子数据为准）
UPDATE product SET stock = stock - 1 WHERE id = 1 AND stock >= 1;

-- 2) 若 ROW_COUNT() = 0，则库存不足，ROLLBACK
-- 3) 否则 INSERT orders / order_item ...

-- 演示回滚：
ROLLBACK;

SET autocommit = 1;
```

## 小结

- 多步写操作应放进同一事务，用提交/回滚保原子性  
- InnoDB 默认 `REPEATABLE READ`；隔离越高，一般并发越受影响  
- 业务失败要显式 `ROLLBACK`，不要假设客户端断开一定会清干净（视连接与设置而定）

## 常见坑 / 面试点

- DDL 可能导致隐式提交，事务里慎混大规模结构变更  
- 「事务」只对支持事务的引擎有效（InnoDB）；MyISAM 无事务  
- 长事务拖住锁与 undo，宜短小  
- 面试：ACID 含义；四种隔离级别与三种读问题的对应关系
