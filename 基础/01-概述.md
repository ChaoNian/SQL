# 01 · 概述

## 目标

建立关系型数据库与 MySQL 的整体图景，能连上服务器并导入 `demo` 库。

## 大纲

### 1. 关系型数据库是什么

- 用表（关系）组织数据：行 = 记录，列 = 字段  
- 表之间通过键关联，减少冗余、保证一致性  
- 与「文档 / 键值」等非关系存储的对比（一句话级）

### 2. 数据模型

- 概念 / 逻辑 / 物理三层；层次、网状、关系等模型对比  
- 关系模型术语与 MySQL 表的对应；1:1 / 1:N / M:N  

### 3. MySQL 扮演的角色

- 客户端 → 服务端 → 存储引擎（入门只记 InnoDB 为默认）  
- 库（schema）→ 表 → 行 / 列  
- 常见使用方式：命令行 `mysql`、图形客户端、应用驱动

### 4. SQL 语言分类

| 类别 | 作用 | 典型语句 |
|------|------|----------|
| DDL | 定义结构 | `CREATE` / `ALTER` / `DROP` |
| DML | 改数据 | `INSERT` / `UPDATE` / `DELETE` |
| DQL | 查数据 | `SELECT` |
| DCL | 权限 | `GRANT` / `REVOKE` |
| TCL | 事务 | `COMMIT` / `ROLLBACK` |

### 5. 连接、字符集与排序规则（入门）

- 主机、端口、用户、密码、默认库  
- `utf8mb4` 与常见排序规则（如 `utf8mb4_0900_ai_ci`）为何重要  
- 查看：`SHOW VARIABLES LIKE 'character_set%';`

### 6. 安装和下载

- 官方下载与安装（见下方专节）  
- 装好后能用命令行或客户端连上本地实例

### 7. MySQL 启动与客户端连接（实践）

- 启动 / 停止服务；命令行与图形客户端连接参数  
- 连通自检与常见报错处理

### 8. 导入演示库

- 执行本目录 `demo.sql`  
- 验证：`USE demo; SHOW TABLES;`

## 安装和下载

学习本笔记需要本机（或远程）有一台可连接的 **MySQL 8.0** 实例。下面以自学最常见的本地安装为例。

### 下载

1. 打开 Oracle 官方下载页： [MySQL Community Downloads](https://dev.mysql.com/downloads/mysql/)  
2. 选择 **MySQL Community Server**，操作系统选 **Windows**（或 macOS / Linux）  
3. Windows 推荐：  
   - **mysql-installer-community**（图形安装向导，省事）  
   - 或 ZIP 包（需自行配置，进阶再用）  
4. 无需登录也可选 “No thanks, just start my download”

> 版本选 **8.0.x** 即可，与本笔记方言一致。

### Windows 安装要点（Installer）

1. 运行安装程序，类型选 **Developer Default** 或 **Server only**（只要服务端 + 客户端）  
2. 记下并设置 **root 密码**（后续所有示例都要用）  
3. 确认 Windows 服务已启动（服务名多为 `MySQL80`）  
4. 默认端口 **3306**；若改过端口，连接时要带上

### 其他环境（简记）

| 环境 | 常见做法 |
|------|----------|
| macOS | 官网 DMG，或 `brew install mysql` |
| Linux | 发行版仓库 / 官方 APT·YUM 源安装 `mysql-server` |
| 不想装本机 | Docker：`docker run -d -p 3306:3306 -e MYSQL_ROOT_PASSWORD=你的密码 mysql:8.0` |

装好后先学会 **启动服务 + 客户端连接**（下一节），再导入 `demo.sql`。

## MySQL 启动与客户端连接（实践）

安装只是把程序放进磁盘；**服务进程起来之后**，客户端才能连上去执行 SQL。

### 1. 启动 / 停止 MySQL 服务

**Windows（本机最常见）**

1. `Win + R` → 输入 `services.msc` → 回车  
2. 找到 **MySQL80**（或安装时起的服务名）  
3. 右键 → **启动** / **停止** / **重新启动**  
4. 建议将启动类型设为「自动」，开机后不用每次手点  

也可在 **以管理员身份** 打开的 PowerShell / CMD 中：

```powershell
# 查看服务状态（服务名按本机为准，常见 MySQL80）
Get-Service -Name MySQL*

# 启动 / 停止
net start MySQL80
net stop MySQL80
```

**macOS**

```bash
# Homebrew 安装时常用
brew services start mysql
brew services stop mysql
brew services restart mysql
```

**Linux（systemd）**

```bash
sudo systemctl start mysql          # 或 mysqld，视发行版而定
sudo systemctl stop mysql
sudo systemctl status mysql
sudo systemctl enable mysql         # 开机自启
```

**Docker**

```bash
docker start <容器名或ID>    # 若当初用 docker run -d 已创建
docker stop <容器名或ID>
```

> 连不上时，先确认服务是 **Running**，再查密码、端口、防火墙。

### 2. 连接前要知道的参数

| 参数 | 本地默认 | 说明 |
|------|----------|------|
| 主机 Host | `127.0.0.1` 或 `localhost` | 远程则填服务器 IP / 域名 |
| 端口 Port | `3306` | 安装时改过则用新端口 |
| 用户 User | `root`（学习用） | 生产应使用最小权限账号 |
| 密码 Password | 安装时设置的 | `-p` 后回车再输入更安全 |
| 数据库 Database | 可先不选 | 登录后再 `USE demo;` |

补充：`localhost` 在 MySQL 里有时走命名管道/套接字；若奇怪连不上，可改试 `127.0.0.1`（强制 TCP）。

### 3. 命令行客户端连接

若 `mysql` 不在 PATH：把安装目录下的 `bin`（如 `C:\Program Files\MySQL\MySQL Server 8.0\bin`）加进系统 PATH，或使用开始菜单里的 **MySQL 8.0 Command Line Client**。

```bash
# 最常见：本地 root，提示输入密码
mysql -u root -p

# 显式指定主机与端口
mysql -h 127.0.0.1 -P 3306 -u root -p

# 登录同时选中库（导入 demo 之后）
mysql -h 127.0.0.1 -P 3306 -u root -p demo
```

登录成功后练习：

```sql
SELECT VERSION();          -- 服务器版本
SELECT USER();             -- 当前用户@主机
STATUS;                    -- 连接与字符集等摘要
SHOW DATABASES;            -- 有哪些库
USE demo;                  -- 切换库（需已导入）
SHOW TABLES;
EXIT;                      -- 退出客户端（服务仍在运行）
```

执行 SQL 文件（在系统命令行，非 mysql 提示符内）：

```bash
mysql -u root -p < demo.sql
```

### 4. 图形客户端连接

以 **MySQL Workbench** / **DBeaver** / **DataGrip** 为例，新建连接时填写：

- Connection type：MySQL  
- Host：`127.0.0.1`  
- Port：`3306`  
- Username：`root`  
- Password：保存到钥匙串/保险库（可选）  
- 测试连接（Test Connection）成功后再打开  

图形客户端适合看表结构、点选结果集；本笔记示例仍以可复制的 SQL 为主，两种方式连的是 **同一实例**。

### 5. 连通自检清单

1. 服务已启动（`services.msc` / `Get-Service` / `systemctl status`）  
2. `mysql -u root -p` 能进入 `mysql>` 提示符  
3. `SELECT VERSION();` 有输出  
4. （可选）Workbench 测试连接为绿色 / 成功  

### 6. 实践中常见报错

| 现象 | 常见原因 | 处理方向 |
|------|----------|----------|
| `Can't connect to ... port 3306` | 服务未启、端口不对、防火墙 | 先启动服务；核对端口 |
| `Access denied for user ...` | 用户名/密码错，或主机权限不匹配 | 核对密码；注意 `root@localhost` vs `root@%` |
| `mysql` 不是内部或外部命令 | PATH 未配置 | 添加 `bin` 到 PATH，或用官方 Command Line Client |
| 服务启动后立刻停止 | 配置/数据目录问题、端口占用 | 看 MySQL 错误日志；检查 3306 是否被占用 |

## 数据模型

数据模型描述「现实世界的信息如何被抽象、组织，并最终存进计算机」。先建立这层图景，后面建表、加约束、做多表查询才不会只是背语法。

### 为什么要有数据模型

- 业务里有「客户、订单、商品」等概念，计算机里需要可存储、可查询的结构  
- 模型约定：有哪些对象、对象有哪些属性、对象之间如何联系  
- 同一业务可以有不同模型；MySQL 走的是 **关系模型**

### 三个层次（由粗到细）

| 层次 | 关注什么 | 常见产物 |
|------|----------|----------|
| 概念模型 | 业务实体与关系（和具体数据库无关） | ER 图：实体、属性、联系 |
| 逻辑模型 | 落到某种数据模型（如关系表、主键外键） | 表结构草案、范式设计 |
| 物理模型 | 在具体产品上怎么存 | MySQL 类型、索引、引擎等 |

入门先会看 ER / 表关系；索引与引擎调优放到进阶。

### 历史上常见的数据模型

| 模型 | 组织方式 | 直觉 |
|------|----------|------|
| 层次模型 | 树：一对多 | 像文件夹目录 |
| 网状模型 | 图：多对多更自然 | 像网状指针 |
| **关系模型** | 二维表 + 键关联 | MySQL / PostgreSQL 等 |
| 文档 / 键值等 | JSON 文档、KV | MongoDB、Redis 等（非本笔记重点） |

本笔记只深入 **关系模型**：用表存数据，用键表达联系，用 SQL 声明式查询。

### 关系模型核心概念

| 术语 | 含义 | 在 MySQL 里常叫 |
|------|------|-----------------|
| 关系（Relation） | 一张二维表 | 表 `TABLE` |
| 元组（Tuple） | 表中的一行 | 行 / 记录 `ROW` |
| 属性（Attribute） | 表中的一列 | 列 / 字段 `COLUMN` |
| 域（Domain） | 属性允许的取值范围 | 数据类型 + 约束 |
| 键（Key） | 能唯一标识元组的属性（组） | 主键、唯一键等 |
| 外键（Foreign Key） | 引用另一关系中键的属性 | `FOREIGN KEY` |

联系类型（概念层常画在 ER 图上）：

- **一对一（1:1）**：一个实体至多对应另一个的一个  
- **一对多（1:N）**：如一个客户有多张订单  
- **多对多（M:N）**：如订单与商品 → 通常拆成中间表（`order_item`）

`demo` 库就是按关系模型拆表的：客户—订单（1:N），订单—商品经明细表（M:N），员工—经理（自关联）。

### 和后面章节的关系

- **SQL / 约束**：把逻辑模型写成 `CREATE TABLE` 与键约束  
- **多表查询**：按外键把多张关系「拼」回业务视图  
- **事务**：保证多步写入后，关系上的业务不变量仍然成立  

## 小结

- 数据模型分概念 / 逻辑 / 物理；MySQL 实现的是关系模型（表 + 键）  
- 关系库用表与键组织数据；多对多往往需要中间表  
- 先分清 DDL / DML / DQL / DCL / TCL，后面章节按类深入  
- 先 **启动服务**，再用命令行或图形客户端连接；通了再导入 `demo` 库

## 常见坑 / 面试点

- `utf8` 在 MySQL 里不等于完整 Unicode，应用场景优先 `utf8mb4`  
- 库名、表名在 Windows / Linux 上大小写敏感性可能不同  
- 「数据库」口语有时指产品（MySQL），有时指某一个 schema  
- 忘记 root 密码：需按官方文档用跳过权限表等方式重置（勿在生产随意操作）  
- `mysql` 命令找不到：把 MySQL 的 `bin` 目录加入系统 PATH，或用开始菜单里的命令行客户端  
- 连不上先查「服务是否启动」，再查密码与端口；`localhost` 与 `127.0.0.1` 行为可能不同  
- 面试常问：关系模型 vs 非关系；ER 里 1:1 / 1:N / M:N 如何落到表  
- 「关系」在术语里指表本身，口语里常被说成「表之间的关联」——二者不同
