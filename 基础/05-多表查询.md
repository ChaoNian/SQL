# 05 · 多表查询

## 目标

熟练写出常见 JOIN，理解自连接与 UNION，能在「连接 vs 子查询」间做简单选择。

## 大纲

### 1. 为什么要多表

- 规范化后数据拆表，查询再关联  
- 连接条件（`ON`）vs 过滤条件（`WHERE`）

### 2. JOIN 种类与写法

- `INNER JOIN`：两边都匹配  
- `LEFT JOIN` / `RIGHT JOIN`：保留一端全部  
- `CROSS JOIN`：笛卡尔积（慎用）  
- 老式逗号多表 + `WHERE` 等价写法（能读即可）

### 3. 自连接

- 同一张表别名两次（如员工与经理）  
- 典型：`employee` 找上级

### 4. 多表关联

- 两表 → 三表（订单 + 客户 + 明细 / 商品）  
- 注意连接顺序与中间表（`order_item`）

### 5. UNION

- `UNION` 去重 vs `UNION ALL` 不去重  
- 列数、类型兼容；`ORDER BY` 放最后

### 6. 连接 vs 子查询

- 连接：适合拼列、集合对齐  
- 子查询：适合「存在性 / 聚合结果再过滤」  
- 可读性与优化器：多数情况二者可改写，以清晰为先

## 示例（占位 · 依赖 demo）

```sql
USE demo;

-- 内连接：订单与客户
SELECT o.id, c.name, o.total_amount
FROM orders o
INNER JOIN customer c ON c.id = o.customer_id;

-- 左连接：所有客户及其订单数
SELECT c.name, COUNT(o.id) AS order_cnt
FROM customer c
LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.id, c.name;

-- 自连接：员工与经理（表结构见 demo）
SELECT e.name AS emp, m.name AS manager
FROM employee e
LEFT JOIN employee m ON m.id = e.manager_id;
```

## 小结

- `INNER` 取交集；`LEFT` 保留左表  
- 自连接靠别名；多对多用中间表  
- `UNION ALL` 通常比 `UNION` 更省

## 常见坑 / 面试点

- `WHERE` 里写 `右表.col = ...` 可能把 `LEFT JOIN` 变成实质内连接  
- 连接条件漏写 → 笛卡尔积，结果行数爆炸  
- `COUNT` 在外连接后对右表列计数时注意 `NULL`  
- 面试：四种 JOIN 结果集差异；`UNION` 与 `JOIN` 不是一类操作
