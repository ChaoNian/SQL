# 05 · 多表查询

## 目标

熟练写出常见 JOIN，理解自连接与 UNION，能在「连接 vs 子查询」间做简单选择。

## 大纲

### 1. 为什么要多表

- 规范化后数据拆表，查询再关联  
- 连接条件（`ON`）vs 过滤条件（`WHERE`）
- 多表关系
  - 项目开发中，在进行数据库表结构设计时，会根据业务需求及业务模块之间的关系，分析并设计表结构，由于业务之间相互关联，所以各个表结构之间也存在着各种联系，基本上分为三种： 一对多(多对一)、多对多、一对一；
  - **一对多(多对一)**
    - 案例：部门与员工之间的关系
    - 关系：一个部门对应多个员工，一个员工对应一个部门
    - 实现：在多的一方建立外键，指向一的一方的主键
  - **多对多**
    - 案例：学生与课程的关系
    - 关系：一个学生可以选修多门课程，一门课程也可以供多个学生选择
    - 实现：建立第三张中间表，中间表至少包含两个外键，分别关联两方主键
  - 一对一
    - 案例：用户 与 用户 详情的关系
    - 关系：一对一关系，多用于单表拆分，将一张表的基础字段放在一张表中，其他详情字段放在另一张表中，以提升操作效率

## 多表查询

### 概述

指从多张表中查询数据。

**笛卡尔积**：数学中两个集合 A、B 的所有组合情况。多表查询时需要通过连接条件消除无效的笛卡尔积。

### 分类

| 分类 | 说明 |
|------|------|
| 连接查询 | 内连接、外连接、自连接 |
| 子查询 | 嵌套在查询中的查询 |

---

### 内连接

相当于查询 A、B **交集**部分的数据。

#### 语法

**隐式内连接：**

```sql
SELECT 字段列表 FROM 表1, 表2 WHERE 条件...;
```

**显式内连接：**

```sql
SELECT 字段列表 FROM 表1 [INNER] JOIN 表2 ON 连接条件...;
```

#### 案例：查询每个员工的姓名及关联部门名称

- 表结构：`emp`、`dept`
- 连接条件：`emp.dept_id = dept.id`

**1. 隐式内连接**

```sql
SELECT emp.name, dept.name
FROM emp, dept
WHERE emp.dept_id = dept.id;

-- 表别名（表名太长时常用）
SELECT e.name, d.name
FROM emp e, dept d
WHERE e.dept_id = d.id;
```

> **注意**：一旦给表起了别名（如 `emp` → `e`），就必须用别名限定字段（与 SQL 解析/执行顺序有关）。
>
> 错误写法：`SELECT e.name, d.name FROM emp e, dept d WHERE emp.dept_id = dept.id;`

**2. 显式内连接（**`INNER JOIN ... ON ...`**）**

```sql
SELECT e.name, d.name
FROM emp e
INNER JOIN dept d ON e.dept_id = d.id;

-- INNER 可省略
SELECT e.name, d.name
FROM emp e
JOIN dept d ON e.dept_id = d.id;
```

---

### 外连接

| 类型 | 说明 |
|------|------|
| 左外连接 | 查询左表全部数据，以及两表交集部分数据 |
| 右外连接 | 查询右表全部数据，以及两表交集部分数据 |

### 自连接

当前表与自身的连接查询；自连接必须使用表别名。

自连接可以是**内连接**，也可以是**外连接**。

#### 语法

```sql
SELECT 字段列表
FROM 表A 别名A
JOIN 表A 别名B ON 条件 ...;
```

#### 案例

**1. 查询员工及其所属领导的名字（内连接）**

```sql
SELECT a.name, b.name
FROM emp a, emp b
WHERE a.managerid = b.id;
```

**2. 查询所有员工及其领导的名字；没有领导的员工也要查出来（左外连接）**

- 表结构：`emp a`、`emp b`（同一张表，两个别名）

```sql
SELECT a.name AS '员工', b.name AS '领导'
FROM emp a
LEFT JOIN emp b ON a.managerid = b.id;
```
### 联合查询（`UNION` / `UNION ALL`）

把多次查询的结果合并起来，形成一个新的查询结果集。

#### 语法

```sql
SELECT 字段列表 FROM 表A ...
UNION ALL
SELECT 字段列表 FROM 表B ...;
```

| 关键字 | 说明 |
|--------|------|
| `UNION ALL` | 直接合并全部数据，不去重 |
| `UNION` | 合并后对结果去重 |

> **注意**：联合查询各段的**列数必须一致**，字段类型也需保持兼容。

#### 案例

**1. 查出薪资低于 5000 的员工，以及年龄大于 50 岁的员工**

```sql
-- 不去重
SELECT * FROM emp WHERE salary < 5000
UNION ALL
SELECT * FROM emp WHERE age > 50;

-- 去重
SELECT * FROM emp WHERE salary < 5000
UNION
SELECT * FROM emp WHERE age > 50;
```

### 子查询

**概念**：SQL 语句中嵌套 `SELECT` 语句，称为嵌套查询，又称子查询。

```sql
SELECT * FROM t1 WHERE column1 = (SELECT column1 FROM t2);
```

子查询外部的语句可以是 `INSERT` / `UPDATE` / `DELETE` / `SELECT` 中的任意一种。

按子查询**结果形态**分类：

| 类型 | 结果形态 | 常用操作符 |
|------|----------|------------|
| 标量子查询 | 单个值（单行单列） | `=` `<>` `>` `>=` `<` `<=` |
| 列子查询 | 一列（可多行） | `IN` / `NOT IN` / `ANY` / `SOME` / `ALL` |
| 行子查询 | 一行（可多列） | `=` / `<>` / `IN` / `NOT IN` |
| 表子查询 | 多行多列 | `IN` |

按子查询**位置**分类：`WHERE` 之后、`FROM` 之后、`SELECT` 之后。

---

#### 1. 标量子查询

子查询返回单个值（数字 / 字符串 / 日期等），即**单行单列**，是最简单的形式。

**案例 1：查询「销售部」的所有员工信息**

```sql
-- a. 查销售部部门 ID
SELECT id FROM dept WHERE name = '销售部';

-- b. 按部门 ID 查员工（假设销售部 id = 4）
SELECT * FROM emp WHERE dept_id = 4;

-- 合并为一句
SELECT * FROM emp
WHERE dept_id = (SELECT id FROM dept WHERE name = '销售部');
```

**案例 2：查询在「黄飞鸿」入职之后的员工信息**

```sql
-- a. 查黄飞鸿的入职日期
SELECT entrydate FROM emp WHERE name = '黄飞鸿';

-- b. 查该日期之后入职的员工
SELECT * FROM emp WHERE entrydate > '2009-02-12';

-- 合并为一句（子查询结果为单行单列）
SELECT * FROM emp
WHERE entrydate > (SELECT entrydate FROM emp WHERE name = '黄飞鸿');
```

---

#### 2. 列子查询

子查询返回**一列**（可以是多行）。

| 操作符 | 说明 |
|--------|------|
| `IN` | 在指定集合范围内（多选一） |
| `NOT IN` | 不在指定集合范围内 |
| `ANY` / `SOME` | 子查询列表中任意一个满足即可（二者等同） |
| `ALL` | 子查询列表中全部值都必须满足 |

**案例 1：查询「销售部」和「市场部」的所有员工信息**

```sql
-- a. 查两个部门的 ID
SELECT id FROM dept WHERE name = '销售部' OR name = '市场部';

-- b. 按部门 ID 查员工
SELECT * FROM emp WHERE dept_id IN (2, 4);

-- 子查询写法
SELECT * FROM emp
WHERE dept_id IN (
  SELECT id FROM dept WHERE name = '销售部' OR name = '市场部'
);
```

**案例 2：查询比财务部所有人工资都高的员工信息**

```sql
-- a. 查财务部所有人工资
SELECT salary FROM emp
WHERE dept_id = (SELECT id FROM dept WHERE name = '财务部');

-- b. 比财务部所有人工资都高（ALL：全部满足）
SELECT * FROM emp
WHERE salary > ALL (
  SELECT salary FROM emp
  WHERE dept_id = (SELECT id FROM dept WHERE name = '财务部')
);
```

**案例 3：查询比研发部其中任意一人工资高的员工信息**

```sql
-- a. 查研发部所有人工资
SELECT salary FROM emp
WHERE dept_id = (SELECT id FROM dept WHERE name = '研发部');

-- b. ANY：括号内任意一个满足即可
SELECT * FROM emp
WHERE salary > ANY (
  SELECT salary FROM emp
  WHERE dept_id = (SELECT id FROM dept WHERE name = '研发部')
);

-- SOME 与 ANY 等价
SELECT * FROM emp
WHERE salary > SOME (
  SELECT salary FROM emp
  WHERE dept_id = (SELECT id FROM dept WHERE name = '研发部')
);
```

---

#### 3. 行子查询

子查询返回**一行**（可以是多列）。

**案例：查询与「张无忌」的薪资及直属领导相同的员工信息**

```sql
-- a. 查张无忌的薪资与直属领导
SELECT salary, managerid FROM emp WHERE name = '张无忌';

-- b. 按固定值匹配
SELECT * FROM emp WHERE salary = 12500 AND managerid = 1;

-- 行构造等价写法（含义：salary = 12500 且 managerid = 1）
SELECT * FROM emp WHERE (salary, managerid) = (12500, 1);

-- 把 (12500, 1) 换成子查询
SELECT * FROM emp
WHERE (salary, managerid) = (
  SELECT salary, managerid FROM emp WHERE name = '张无忌'
);
```

---

#### 4. 表子查询

子查询返回**多行多列**。常用操作符：`IN`。

**案例 1：查询与「陆远桥」「宋远桥」职位和薪资相同的员工信息**

```sql
-- a. 查两人职位与薪资
SELECT job, salary FROM emp
WHERE name = '陆远桥' OR name = '宋远桥';

-- b. 用表子查询匹配
SELECT * FROM emp
WHERE (job, salary) IN (
  SELECT job, salary FROM emp
  WHERE name = '陆远桥' OR name = '宋远桥'
);
```

**案例 2：查询入职日期在 `2006-01-01` 之后的员工信息，及其部门信息**

```sql
-- a. 入职日期之后的员工
SELECT * FROM emp WHERE entrydate > '2006-01-01';

-- b. 子查询放在 FROM 后，再关联部门表
SELECT e.*, d.*
FROM (SELECT * FROM emp WHERE entrydate > '2006-01-01') e
LEFT JOIN dept d ON e.dept_id = d.id;
```

| 选课数据 | 含义 |
|----------|------|
| 学生 1 | 选了课 1、2、3（Java / PHP / MySQL） |
| 学生 2 | 选了课 2、3（PHP / MySQL） |
| 学生 3 | 选了课 4（Hadoop） |

> 前提：库中已有 `student` 表，且存在 `id` 为 1、2、3 的学生记录，否则外键插入会失败。

### 2. JOIN 种类与写法

- `INNER JOIN`：两边都匹配  
- `LEFT JOIN` / `RIGHT JOIN`：保留一端全部  
- `CROSS JOIN`：笛卡尔积（慎用）  
- 老式逗号多表 + `WHERE` 等价写法（能读即可）

### 3. 自连接

- 同一张表别名两次（如员工与经理）  
- 典型：`employee` 找上级

### 4. 多表关联

- 两表 → 三表（订单 + 客户 + 明细 / 商品）  
- 注意连接顺序与中间表（`order_item`）

### 5. UNION

- `UNION` 去重 vs `UNION ALL` 不去重  
- 列数、类型兼容；`ORDER BY` 放最后

### 6. 连接 vs 子查询

- 连接：适合拼列、集合对齐  
- 子查询：适合「存在性 / 聚合结果再过滤」  
- 可读性与优化器：多数情况二者可改写，以清晰为先

## 示例（占位 · 依赖 demo）

```sql
USE demo;

-- 内连接：订单与客户
SELECT o.id, c.name, o.total_amount
FROM orders o
INNER JOIN customer c ON c.id = o.customer_id;

-- 左连接：所有客户及其订单数
SELECT c.name, COUNT(o.id) AS order_cnt
FROM customer c
LEFT JOIN orders o ON o.customer_id = c.id
GROUP BY c.id, c.name;

-- 自连接：员工与经理（表结构见 demo）
SELECT e.name AS emp, m.name AS manager
FROM employee e
LEFT JOIN employee m ON m.id = e.manager_id;
```

## 多表查询案例

### 1. 查询员工的姓名、年龄、职位、部门信息

> **掌握要点**：隐式内连接——多表用逗号 + `WHERE` 写等值连接，拼出员工与部门字段。

- 表：`emp`、`dept`
- 连接条件：`emp.dept_id = dept.id`

```sql
SELECT e.name, e.age, e.job, d.name
FROM emp e, dept d
WHERE e.dept_id = d.id;
```

### 2. 查询年龄小于 30 岁的员工姓名、年龄、职位、部门信息（显式内连接）

> **掌握要点**：显式内连接 + 过滤——`INNER JOIN ... ON` 写连接，`WHERE` 写业务条件（如年龄）。

- 表：`emp`、`dept`
- 连接条件：`emp.dept_id = dept.id`

```sql
SELECT e.name, e.age, e.job, d.name
FROM emp e
INNER JOIN dept d ON e.dept_id = d.id
WHERE e.age < 30;
```

### 3. 查询拥有员工的部门 ID、部门名称

> **掌握要点**：交集去重——内连接只保留有匹配的部门，用 `DISTINCT` 去掉重复部门行。

- 表：`emp`、`dept`
- 连接条件：`emp.dept_id = dept.id`

```sql
SELECT DISTINCT d.id, d.name
FROM emp e, dept d
WHERE e.dept_id = d.id;
```

### 4. 查询年龄大于 40 岁的员工及其部门名称（无部门也要展示）

> **掌握要点**：左外连接——主表（员工）全保留；无部门时右表字段为 `NULL` 也要查出。

- 表：`emp`、`dept`
- 连接条件：`emp.dept_id = dept.id`

```sql
SELECT e.*, d.name
FROM emp e
LEFT JOIN dept d ON e.dept_id = d.id
WHERE e.age > 40;
```

### 5. 查询所有员工的工资等级

> **掌握要点**：非等值连接 / 区间匹配——薪资与等级表用 `BETWEEN losal AND hisal`（或 `>=` / `<=`）。

- 表：`emp`、`salgrade`
- 连接条件：`emp.salary` 落在 `salgrade.losal` ~ `salgrade.hisal` 区间

```sql
SELECT e.*, s.grade, s.losal, s.hisal
FROM emp e, salgrade s
WHERE e.salary >= s.losal AND e.salary <= s.hisal;

-- 等价写法
SELECT e.*, s.grade, s.losal, s.hisal
FROM emp e, salgrade s
WHERE e.salary BETWEEN s.losal AND s.hisal;
```

### 6. 查询「研发部」所有员工的信息及工资等级

> **掌握要点**：三表联合——部门等值连接 + 薪资区间连接，再叠加部门名过滤。

- 表：`emp`、`dept`、`salgrade`
- 连接条件：`emp.salary BETWEEN salgrade.losal AND salgrade.hisal`，`emp.dept_id = dept.id`
- 查询条件：`dept.name = '研发部'`

```sql
SELECT e.*, s.grade
FROM emp e, dept d, salgrade s
WHERE e.dept_id = d.id
  AND e.salary BETWEEN s.losal AND s.hisal
  AND d.name = '研发部';
```

### 7. 查询「研发部」员工的平均工资

> **掌握要点**：多表聚合——先连接再 `AVG`，按部门条件求平均工资。

- 表：`emp`、`dept`
- 连接条件：`emp.dept_id = dept.id`

```sql
SELECT AVG(e.salary)
FROM emp e, dept d
WHERE e.dept_id = d.id
  AND d.name = '研发部';
```

### 8. 查询工资比「灭绝」高的员工信息

> **掌握要点**：标量子查询——用「某人薪资」作比较基准（单值）。

```sql
-- a. 查「灭绝」的薪资
SELECT salary FROM emp WHERE name = '灭绝';

-- b. 查比她工资高的员工
SELECT * FROM emp
WHERE salary > (SELECT salary FROM emp WHERE name = '灭绝');
```

### 9. 查询比平均薪资高的员工信息

> **掌握要点**：聚合子查询——用「全表平均值」作比较基准。

```sql
-- a. 查平均薪资
SELECT AVG(salary) FROM emp;

-- b. 查比平均薪资高的员工
SELECT * FROM emp
WHERE salary > (SELECT AVG(salary) FROM emp);
```

### 10. 查询低于本部门平均工资的员工信息

> **掌握要点**：相关子查询——外层每行关联本部门，与「本部门平均」比较。

```sql
-- a. 查指定部门平均薪资
SELECT AVG(e1.salary) FROM emp e1 WHERE e1.dept_id = 1;
SELECT AVG(e1.salary) FROM emp e1 WHERE e1.dept_id = 2;

-- b. 低于本部门平均工资的员工（相关子查询）
SELECT *,
       (SELECT AVG(e1.salary) FROM emp e1 WHERE e1.dept_id = e2.dept_id) AS '平均'
FROM emp e2
WHERE e2.salary < (
  SELECT AVG(e1.salary) FROM emp e1 WHERE e1.dept_id = e2.dept_id
);
```

### 11. 查询所有部门信息，并统计各部门员工人数

> **掌握要点**：`SELECT` 后标量子查询——按部门统计人数，一行一部门一带计数。

```sql
SELECT d.id, d.name,
       (SELECT COUNT(*) FROM emp e WHERE e.dept_id = d.id) AS '人数'
FROM dept d;

-- 核对：某个部门人数
SELECT COUNT(*) FROM emp WHERE dept_id = 1;
```

### 12. 查询所有学生的选课情况（学生名称、学号、课程名称）

> **掌握要点**：多对多三表——学生 ↔ 中间表 ↔ 课程，两条外键条件缺一不可。

- 表：`student`、`course`、`student_course`
- 连接条件：`student.id = student_course.studentid`，`course.id = student_course.courseid`

```sql
SELECT s.name, s.no, c.name
FROM student s, student_course sc, course c
WHERE s.id = sc.studentid
  AND sc.courseid = c.id;
```

## 小结

### 1. 多表关系

| 关系 | 实现 |
|------|------|
| **一对多** | 在多的一方建立外键，指向一的一方的主键 |
| **多对多** | 建立第三张中间表，中间表至少包含两个外键，分别关联两方主键 |
| **一对一** | 在任意一方加入外键，关联另外一方的主键，并且设置外键为唯一（`UNIQUE`）；一对一多用于单表拆分 |

### 2. 多表查询

**内连接**

```sql
-- 隐式
SELECT ... FROM 表A, 表B WHERE 条件 ...;

-- 显式
SELECT ... FROM 表A [INNER] JOIN 表B ON 条件 ...;
```

**外连接**

```sql
-- 左外
SELECT ... FROM 表A LEFT [OUTER] JOIN 表B ON 条件 ...;

-- 右外
SELECT ... FROM 表A RIGHT [OUTER] JOIN 表B ON 条件 ...;
```

**自连接**

```sql
SELECT ... FROM 表A 别名1, 表A 别名2 WHERE 条件 ...;
-- 也可写成 JOIN ... ON ...；自连接必须使用表别名
```

**子查询**（按结果形态）

| 类型 | 结果 |
|------|------|
| 标量子查询 | 单个值（单行单列） |
| 列子查询 | 一列（可多行） |
| 行子查询 | 一行（可多列） |
| 表子查询 | 多行多列 |

> 另：`UNION` / `UNION ALL` 用于合并多次查询结果；`UNION ALL` 通常比 `UNION` 更省。

## 常见坑 / 面试点

- `WHERE` 里写 `右表.col = ...` 可能把 `LEFT JOIN` 变成实质内连接  
- 连接条件漏写 → 笛卡尔积，结果行数爆炸  
- `COUNT` 在外连接后对右表列计数时注意 `NULL`  
- 面试：四种 JOIN 结果集差异；`UNION` 与 `JOIN` 不是一类操作
